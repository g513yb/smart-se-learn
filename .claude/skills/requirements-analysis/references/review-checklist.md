# 五查评审表

评审人不能是需求负责人。逐条给出通过 / 不通过，并写依据。

| 检查 | 问题 | 结果 |
|---|---|---|
| 有据 | 原文摘录是否与 S/D/R 逐句一致？每条来源能否回溯？推断是否都已转 Q？故事卡是否只重述原话、没有新增？去掉这条会损失什么？ | |
| 完整 | 角色、触发、异常、边界是否覆盖？故事卡字段是否齐全？非功能是否按清单问过？ | |
| 一致 | 是否与其他需求、术语表、愿景冲突？冲突检查是否记录结论、比对条目和未覆盖项？同一概念是否同名？ | |
| 可测 | 验收标准是否可观察、无歧义、可执行？ | |
| 可追踪 | ID、追踪矩阵、变更记录是否已更新？ | |

## 评审记录

- 评审人：
- 日期：
- 不通过项与处理：
- 结论：通过 / 退回

评审结果写回 `02-backlog.md` 的评审结果 / 评审日期；确认人 / 确认日期由对话成员填写。

## 常见退回原因

- 来源栏只写“讨论过”，没有 S/D/R 编号
- 验收标准写“体验良好”“响应及时”
- 需求里出现技术方案
- 角色只写“用户”，没有具体角色
- 未决问题没有指派确认人
