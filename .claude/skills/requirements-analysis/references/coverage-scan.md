# 模块覆盖扫描

模块首次进入时执行。只产出问题与覆盖状态，不产出需求。

## 输入

| 输入 | 来源 | 缺失时 |
|---|---|---|
| 模块边界 | `00-vision.md`、`context.md` | 先问范围，不继续扫描 |
| 六维固定提问 | `elicitation-playbook.md` | 不执行 |
| 已确认需求 | `02-backlog.md` 本模块 | 视为无 |
| 已问待答 Q | `07-questions.md` 本模块 | 视为无 |
| 已回答 Q / 稳定知识 | `07-questions.md`、`context.md`、`glossary.md` | 视为无 |
| 模块 brief | `research/<模块>.md` | 不做 P 驱动的主动补充；仍可按六维问开放问题 |

## 过程

对每个维度、每个固定提问：

1. 已有确认需求覆盖 → **有需求**
2. 已回答 Q 或稳定知识覆盖 → **已确认**
3. 有待答 Q 覆盖 → **已问待答**
4. 模块明确不涉及 → **不适用**
5. 以上都没有 → **未问**；生成一个开放问题，写入 `07-questions.md`
6. 模块边界不清 → **无法判断**；先生成范围问题，不生成功能问题

每条判断必须记录：固定提问、已知依据、判断结果、缺口原因、新 Q（如有）。

## 闭集规则

- 六维清单是闭集，不得自行增加清单外问题
- 如认为需要新维度或新提问，标为“清单外建议”，写明依据，交用户批准后才能加入 `elicitation-playbook.md`
- 不得把来源能力直接写成需求；扫描只产出问题

## 输出

1. `docs/requirements/coverage-scan.md`：本次扫描记录
2. `coverage.md`：更新模块六维状态
3. `07-questions.md`：新增 Q，带维度、依据、状态
4. 不产出：需求、故事卡、功能清单

## 状态映射

| 扫描判断 | `coverage.md` |
|---|---|
| 有确认需求 | 有需求 |
| 已回答 / 稳定知识 | 已确认 |
| 有待答 Q | 已问待答 |
| 未覆盖 | 未问；建 Q 后改为已问待答 |
| 不适用 | 不适用 |
| 无法判断 | 无法判断 |
