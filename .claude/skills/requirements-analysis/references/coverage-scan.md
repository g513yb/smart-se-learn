# 模块覆盖扫描

模块首次进入时执行。只产出问题与覆盖状态，不产出需求。

## 1. 前置检查

| 检查 | 依据 | 不通过时 |
|---|---|---|
| 模块边界明确 | `00-vision.md`、`context.md`、`glossary.md`、`02-backlog.md` | 只生成一个范围问题，停止扫描 |
| 六维固定提问可用 | `elicitation-playbook.md` | 报告缺失，不执行 |
| 输入清单可用 | 下表 | 逐项标记“缺失”，不凭记忆补 |

模块边界确认属于流程 1.0；1.0 未通过时，本扫描不执行。边界不明确时，先查 `07-dialogue.md` 是否已有范围 Q；有则引用，不重复生成。

## 2. 输入

| 输入 | 来源 | 缺失时 |
|---|---|---|
| 模块边界 | `00-vision.md`、`context.md` | 停止，先问范围 |

| S 用户原话/回答 | `07-dialogue.md` 本模块 | 视为无 |
| 稳定知识 | `context.md`、`glossary.md` | 视为无 |

| 模块 brief | `research/<模块>.md` | 只用于提问依据，不作覆盖依据 |

## 3. 执行顺序

角色 → 旅程 → 对象 → 规则 → 横切 → 质量。每个维度按子提问顺序，不跳项。

## 5. 每个子提问的判断

按以下顺序查找依据：

1. S 用户原话/回答（状态已记录或已确认）
2. 已确认需求（`REQ-`）
3. 稳定知识（`context.md`、`glossary.md`）
4. 已问待答 Q
5. NFR / 愿景（`NFR-`、`R-`）
6. 模块 brief（`P-`）：只帮助提问，不作覆盖依据

分类：

| 状态 | 条件 |
|---|---|
| 有需求 | 有确认需求明确覆盖本子提问 |
| 已确认 | 有 S 用户原话/回答或稳定知识明确覆盖 |
| 已问待答 | 有未回答 Q 明确覆盖 |
| 部分覆盖 | 有 Q/需求只覆盖本子提问的一部分 |
| 未覆盖 | 没有任何明确依据 |
| 不适用 | 有明确的模块范围声明排除本子提问 |
| 无法判断 | 缺术语、规则或范围，无法判断 |

“对标调研”列使用“已调研”：本模块已有 brief，不表示六维覆盖。

判定规则：

- **必须显式引用**：每个非“未覆盖”结论都要写 `Q-`、`REQ-`、`R-`、`NFR-` 编号或 `context/glossary` 条目；没有引用就是未覆盖。
- **同主体、同范围、同属性**：引用必须覆盖本子提问的主体和范围；不确定时写“部分覆盖”或“无法判断”，不写“已确认”。
- **不适用必须有明确排除声明**：AI 自己判断模块不涉及，不算不适用。
- **P 不作覆盖依据**：`P-` 观察只能用于生成问题，不能证明本模块已有覆盖。

## 6. 生成问题

- 部分覆盖 / 未覆盖 → 生成开放问题
- 无法判断 → 生成范围或定义问题
- 不适用 → 不生成
- 已确认 / 有需求 / 已问待答 → 不重复生成

Q 模板：

```
Q-xxx 【维度 / 子提问】<具体开放问题>
依据：固定提问「<子提问原文>」+ 缺口：<没有依据 / 只有 S-xxx 或 Q-xxx 覆盖部分 / 缺术语...>；如引用来源观察，追加 P-xxx
回答人：<姓名或角色>
关联需求：待建
```

固定提问本身的依据写 `固定提问（coverage-scan.md）`（团队规定使用六维清单），不要编造 P 依据。

## 7. 维度聚合

| 子提问情况 | 维度状态 |
|---|---|
| 全部适用项由确认需求覆盖 | 有需求 |
| 全部适用项已覆盖（需求或已确认知识） | 已确认 |
| 任一无法判断 | 无法判断 |
| 任一未覆盖 | 未问；建 Q 后改已问待答 |
| 任一已问待答或部分覆盖 | 已问待答 |
| 全部不适用 | 不适用 |

“部分覆盖”在 `coverage.md` 中记为“已问待答”。

## 8. 输出

1. `docs/requirements/coverage-scan.md`：逐子提问记录
2. `coverage.md`：维度状态
3. `07-dialogue.md`：新增 S（如有用户原话）和 Q，带维度、依据、状态
4. 不产出：需求、故事卡、功能清单
