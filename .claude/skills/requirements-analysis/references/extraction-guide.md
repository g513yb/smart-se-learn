# 提取规则

需求文件的内容不是 AI 原创，而是从规定来源提取。提取不是改写，更不是补全。

## 1. 合法来源

| 来源 | 能提取什么 | 不能做什么 |
|---|---|---|
| `S` | 用户原话、回答、确认 | 不改写、不补全 |
| `D` | 团队明确决定 | 不替人决定 |
| `R` | 文档明确写出的内容 | 不推论、不跨章节拼凑 |
| `P` | 用户可见行为，仅用于提问 | 不直接写成需求 |
| `Q` | 问题 | 不作来源 |
| `I` | 推断 | 不进入已确认 |

## 2. 原文摘录

每张故事卡必须有“原文摘录”字段：

- 从 `S` 提取：逐字复制相关句子，标 `S-ID`
- 从 `R` 提取：复制条款或章节原文，标 `R-ID`
- 从 `D` 提取：复制决策原文，标 `D-ID`
- 多条来源分别列出，不合并成一句概述
- 原文摘录不能为空；为空说明没有来源，写 Q，不写故事卡

## 3. 从 S 提取

1. 先记 `S-xxx`，保留原句
2. 把支持该故事的句子逐字复制到“原文摘录”
3. 只做重述、拆分、归一化；不改范围、主体、条件、结果
4. 同义归一化只允许不改变含义的情况，例如“老师”→“教师”
5. 原文没有的角色、字段、规则、指标 → Q
6. “以便”价值必须有原文；没有则 Q，不写进故事

## 4. 从 R 提取

1. 引用到章节或条款，不能只写文档名
2. 只提取文档明确写出的内容
3. 不把“通常做法”或“推论”写成文档内容
4. 文档之间冲突：记录双方，生成 Q
5. 文档过时或只有部分内容：标证据强度

## 5. 从 P 提取

`P` 只生成 Q：

1. 判定“用户可见行为”：用户能看到、做到、得到什么；不是架构、算法、数据模型、技术栈
2. 每条观察带 `P-ID` 和证据强度
3. 观察写成“用户能……，以便……”或“用户看到……”
4. 设计细节 → `DSN-`
5. 把观察转成问题，例如：“P-004 中 Canvas 教师能看周活动；我们是否需要？Q-xxx”
6. 用户回答后，答案记 `S`；需求来源写 `S`，不写 `P`

## 6. 从 D 提取

- 记录决策原文、决策人、日期
- 不把“会议讨论”写成 `D`；只有明确决定才是 `D`
- 决策变更：旧 `D` 标废弃，新建 `D`
- 优先级、冲突处理、基线变更都必须有 `D`

## 7. 字段来源矩阵

| 字段 | 允许来源 | 没有来源时 |
|---|---|---|
| ID | 编号规则 | — |
| 标题 | `S/D/R` | Q |
| 故事 | `S/D/R` | Q |
| 原文摘录 | `S/D/R` | Q；不写故事卡 |
| 来源 | `S/D/R` | Q |
| 验收标准 | `S/D/R` | Q |
| 优先级 | `D/S`（人决定） | 待定 |
| 优先级依据 | `D/S/Q` | 待定 |
| 负责人 / 评审人 | 人指定 | 待指定 |
| 评审结果 / 日期 | 评审人 | 待评审 |
| 冲突检查 | 现有需求、NFR、愿景、术语、上下文 | 无法判断 / Q |
| 确认人 / 日期 | 人确认 | 待确认；状态不升级 |
| 依赖 | `S/REQ` | 无 / 待确认 |
| 状态 | AI 只能写候选 | 人决定其余状态 |
| 未决问题 | `Q` | 无则写“无” |

## 8. 提取步骤

1. 收集 `S/D/R`
2. 逐字摘录到“原文摘录”
3. 只从摘录写故事
4. 只从摘录或回答写验收标准
5. 按字段矩阵逐项检查；缺的写 Q 或“待确认”
6. 检查是否新增角色、字段、规则、指标
7. 过冲突检查和 DoR

## 9. 评审对照

评审人逐句对照：

- 故事卡每个句子能否在原文摘录中找到依据？
- 有没有新增范围、条件、角色、字段、规则？
- “以便”价值是否来自原文？
- 验收标准的前置条件是否来自原文或回答？
- 找不到依据 → 退回或转 Q

## 10. 示例

### 合格

`S-001`：“老师上传讲义后，学生应该能下载。下载失败要给出提示。”

原文摘录：

> 老师上传讲义后，学生应该能下载。下载失败要给出提示。（S-001）

故事：

> 作为学生，我希望下载教师上传的讲义。（价值未说明，见 Q-xxx；不写“以便”）

验收标准：

> Given 教师已上传讲义，When 学生下载讲义，Then 学生获得讲义；下载失败时给出提示。

未决问题：价值、登录、权限、提示内容、重试。

### 不合格

- 加“以便复习/离线学习”：原文没有价值
- 加“重试按钮”：原文只说“给出提示”
- 加“登录后”：原文没有登录
- 加“视频也可下载”：原文只说讲义
- 把“老师”改成“任课教师”：改变了角色范围

## 11. 常见错误

- 把 `P` 观察直接写成需求
- 把未回答的 `Q` 当成答案
- 把“通常做法”写进原文摘录
- 故事卡写得很顺，但原文摘录找不到对应句子
- 评审只看故事卡，不回看原文
