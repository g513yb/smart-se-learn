# 问答记录

需求的第一来源。未回答的问题是待确认清单；已回答的问题是需求的原始出处。

## 模板

| 编号 | 问题 | 依据 | 状态 | 回答 | 回答人 | 日期 | 关联需求 |
|---|---|---|---|---|---|---|---|
| Q-001 | 示例：登录使用什么凭证？ | 用户描述 | 待回答 | | | | |

状态：待回答 / 已确认 / 已废弃

## 规则

- 问题必须具体、开放、可回答；不要用“是否还需要别的”这类空问题。
- “依据”必填：`P-` 来源观察、`Q-` 用户原话、`D-` 决策或 `R-` 文档。没有依据的问题只能作为开放问题，不能写成需求候选。
- 先开放提问；确实需要选项时，把选项标为“建议”，不替回答人决定。
- “没反对”不算确认。批量确认必须写明编号范围，例如“Q-001 至 Q-005 确认”。
- 记录回答人姓名和日期；回答尽量保留原话，转述需标注“转述”。
- 回答人必须是姓名；只知道角色时写“待确认（角色）”，不按已确认处理。
- 已确认的问题保留，不删除；后续需求引用同一编号。
- AI 只能记录确认，不能代替人确认。
- 新问题按顺序编号，不复用、不跳号。
