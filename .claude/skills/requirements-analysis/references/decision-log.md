# 决策记录规则

`D` = 项目级明确决策；AI 只记录，不能替人决策。
决策来源可以是 `S/Q/REQ/P`。

## 1. 什么时候写

- D 只记录项目级决策：范围、基线、冲突、跨需求规则、方向取舍、其他明确项目决策。
- 内容确认不写 D：采用 AI 草案、接受 AI 提取的最终版本、选择措辞/结构。
- 优先级由人决定；backlog 不记录优先级依据或 D。
- `docs/team.md` 和 `docs/STATUS.md` 的建立与更新不是项目决策，不写 D；不记录确认人/日期。
- 管理/流程规则变更记录在 `CLAUDE.md` 和 skill references，不写项目 D。
- 不是每个讨论都写 D；只有明确决定才写。
- 会议讨论、倾向、建议不是 D。

## 2. 判断是否需要 D

需要 D：

1. 改变项目做什么/不做什么；
2. 改变范围、基线或跨需求规则；
3. 在两个都成立的方案之间取舍，且取舍结果需要以后记住；
4. 解决两条已确认内容之间的冲突；
5. 放弃/暂停某个方向。

不需要 D：

- 采用 AI 给出的故事、术语、事实、NFR 草案；
- 选择措辞、格式、结构；
- 单条内容的正常确认；
- 优先级。

## 3. 字段

| 字段 | 内容 |
|---|---|
| D-ID | `D-<三位序号>` |
| 决策 | 一句话，明确、可执行；二选一时写“采用 X，不采用 Y”摘要 |
| 依据 | `S/Q/REQ/P` 编号；没有依据先提问 |
| 影响需求 / 文档 | 受影响的 REQ、文档或模块 |
| 状态 | 已决定 / 已废弃 |

## 4. 二选一场景

- 两个选项只是同一目标文件的不同内容版本 → 不写 D；人选中的内容写入目标文件。
- 两个选项代表不同的范围、规则、基线或方向 → 写 D；记录采用/不采用的摘要、选择理由、影响、状态。
- 都不同意、要求重做 → 不写 D；改进方向记 Q 或 S；AI 重做；最终选择再判断是否需要 D。

## 5. 规则

- AI 不能替人做决定。
- 新决定取代旧决定时，旧 D 标“已废弃”，新建 D；不删除旧记录。
- 优先级由人决定；backlog 不记录优先级依据或 D。

## 6. 基线变更

- 项目基线是否记 D，按对应文件的规则（`vision-guide.md`、`persona-guide.md`）；本文件只定义 D 的写法。
- 项目基线变更由人确认；确认在对话中完成，不记录确认人/日期；无评审。该规则本身是管理决策，记录在 `CLAUDE.md`/skill，不另立项目 D。

## 7. AI 边界

- 可以：记录人的决定、检查字段是否完整、引用到 backlog。
- 不可以：替人决定、把讨论写成 D、把 AI 的建议写成 D。
