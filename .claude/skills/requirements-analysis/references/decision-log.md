# 决策记录规则

`D` = 团队明确决策；AI 只记录，不能替人决策。
决策来源可以是 `S/Q/REQ/R/P`；决策人必须是姓名。

## 1. 什么时候写

- D/CR 只记录项目决策：需求、范围、优先级、冲突、项目基线。
- 管理/流程规则变更（确认权、工作流、文档规则）记录在 `CLAUDE.md` 和 skill references，不写项目 D/CR。
- 不是每个讨论都写 D；只有明确决定才写。
- 会议讨论、倾向、建议不是 D。

## 2. 字段

| 字段 | 内容 |
|---|---|
| D-ID | `D-<三位序号>` |
| 日期 | 决定日期 |
| 决策 | 一句话，明确、可执行 |
| 依据 | `S/Q/REQ/R/P` 编号；没有依据先提问 |
| 决策人 | 姓名；AI 不能填 |
| 影响需求 / 文档 | 受影响的 REQ、文档或模块 |
| 状态 | 已决定 / 已废弃 |

## 3. 规则

- 决策人必须是姓名；AI 不能填决策人，也不能替人做决定。
- 新决定取代旧决定时，旧 D 标“已废弃”，新建 D；不删除旧记录。
- 优先级决定在 `02-backlog.md` 的“优先级依据”列引用 D-ID。
- 冲突处理决定在 `06-changes.md` 的“决策”列引用 D-ID。

## 4. 基线变更

- 项目基线变更（愿景、范围、非目标、角色）必须记 D，并在 `06-changes.md` 留痕。
- 项目基线变更的 D 记录确认人姓名和日期；D 表的“决策人”即确认人，“日期”即确认日期。
- 临时规则：当前文件存储无应用层，项目基线变更由任一成员一人确认；另一人可评审。应用层上线后恢复两人会签。该规则本身是管理决策，记录在 `CLAUDE.md`/skill，不另立项目 D/CR。应用层上线后重新评估是否恢复两人会签。

## 5. AI 边界

- 可以：记录人的决定、检查字段是否完整、引用到 backlog/CR。
- 不可以：替人决定、编决策人姓名、编日期、把讨论写成 D、把 AI 的建议写成 D。
