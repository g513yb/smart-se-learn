# 决策记录规则

`D` = 团队明确决策；AI 只记录，不能替人决策。
决策来源可以是 `S/Q/REQ/P`；决策人必须是姓名。

## 1. 什么时候写

- D 只记录项目决策：需求、范围、优先级、冲突、项目基线。
- `docs/team.md` 和 `docs/STATUS.md` 的建立与更新不是项目决策，不写 D；不记录确认人/日期。
- 管理/流程规则变更（确认权、工作流、文档规则）记录在 `CLAUDE.md` 和 skill references，不写项目 D。
- 不是每个讨论都写 D；只有明确决定才写。
- 会议讨论、倾向、建议不是 D。

## 2. 字段

| 字段 | 内容 |
|---|---|
| D-ID | `D-<三位序号>` |
| 日期 | 决定日期 |
| 决策 | 一句话，明确、可执行 |
| 依据 | `S/Q/REQ/P` 编号；没有依据先提问 |
| 决策人 | 姓名；AI 不能填 |
| 影响需求 / 文档 | 受影响的 REQ、文档或模块 |
| 状态 | 已决定 / 已废弃 |

## 3. 规则

- 决策人必须是姓名；AI 不能填决策人，也不能替人做决定。
- 新决定取代旧决定时，旧 D 标“已废弃”，新建 D；不删除旧记录。
- 优先级由人决定；backlog 不记录优先级依据或 D。

## 4. 基线变更

- 项目基线是否记 D、是否建 CR，按对应文件的规则（`vision-guide.md`、`persona-guide.md`）；本文件只定义 D 的写法。
- 项目基线变更由人确认；确认在对话中完成，不记录确认人/日期；无评审。该规则本身是管理决策，记录在 `CLAUDE.md`/skill，不另立项目 D。

## 5. AI 边界

- 可以：记录人的决定、检查字段是否完整、引用到 backlog/CR。
- 不可以：替人决定、编决策人姓名、编日期、把讨论写成 D、把 AI 的建议写成 D。
