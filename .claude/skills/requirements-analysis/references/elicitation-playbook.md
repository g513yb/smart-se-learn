# 提问手册

提问的目标是让缺口暴露，不是让 AI 替人回答。所有问题编号进 `07-dialogue.md`；用户原话记为 S，问题记为 Q。缺口的定义与判定步骤见 `gap-check.md`。

## 两种提问来源

| 来源 | 依据写法 | 例子 |
|---|---|---|
| 用户描述 | 引用用户原话 S-xxx | “你说学生登录后学习课程，但未说明课程范围；S-001” |
| AI 主动发现 | 引用 P 编号与观察，并关联 Q | “P-004 中 Canvas 提供周活动视图；我们是否需要类似视图？Q-014” |

没有依据时，只能问开放问题（“你们还需要哪些记录视图？”），不能提出“应该有 X”的需求候选。

## 一条需求：成形四问

1. 角色：还有谁做这件事？谁不做？
2. 触发：什么条件下发生？前置条件是什么？
3. 异常：失败、越权、超时、重复提交、边界值时怎样？
4. 完成：怎么判断做成了？看到什么？留下什么记录？

## 一个模块：六维扫描

进入模块前按 `coverage-scan.md` 执行。本表是维度摘要；每个维度拆成 27 个固定子提问，逐项判断。扫描记录写入 `docs/requirements/coverage-scan.md`，状态写入 `coverage.md`。六维清单是闭集，不得自行增加清单外问题。

| 维度 | 扫描问题 |
|---|---|
| 角色 | 谁参与？还有谁？各自目标是什么？谁被排除？ |
| 旅程 | 首次、日常、结束、异常四条路径分别怎样？ |
| 对象 | 产生哪些数据？从哪来、存哪、谁看、谁改、何时删？ |
| 规则 | 有哪些业务规则？谁定的？例外是什么？ |
| 横切 | 权限、通知、检索、导出、审计要不要？ |
| 质量 | 性能、可用性、安全、隐私、可解释性目标是什么？依据是什么？ |

## 提问规则

- 先开放提问；需要选项时标“建议”，不替回答人决定。
- 一个问题只问一件事。
- 问题必须具体到本模块，不问“还需要什么”这类空话。
- 优先问能改变范围或验收标准的问题。
- 已被回答的问题不重复问；引用原 Q 编号。
- 设计问题转成用户可见问题再问，例如“竞品用知识追踪” → “学生是否需要个性化的下一步建议”。
