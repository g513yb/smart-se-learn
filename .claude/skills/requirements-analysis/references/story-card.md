# 故事卡

## 模板

| 字段 | 内容 |
|---|---|
| ID | `REQ-<模块缩写>-<三位序号>` |
| 标题 | 一句话 |
| 故事 | 作为〈角色〉，我希望〈行为〉，以便〈价值〉 |
| 验收标准 | Given ... When ... Then ...（主流程至少一条，异常流另列） |
| 优先级 | Must / Should / Could / Won't |
| 负责人 | 姓名 |

## 填写规则

- 一条故事只表达一个用户价值。
- 只写“做什么”，不写“怎么做”；技术方案留给设计。
- 验收标准必须可观察；写不出 Then，说明需求未成形，写 Q。
- 故事只写已确认内容；未确认的细节写 Q，不写进故事。
- 用户原话存入 S；故事可以从 S、已写入文件或 AI 提议中生成；AI 提议标“AI 提议”，人确认后写入。
- 整理后与原意不一致时，写 Q，重新确认。
- 优先级由人决定；AI 只给建议。
- 负责人从 `team.md` 取；无匹配问人。

## 示例（非项目需求）

| 字段 | 内容 |
|---|---|
| ID | REQ-LEARN-001 |
| 标题 | 学生查看已授权课程 |
| 故事 | 作为学生，我希望查看我已被授权的课程，以便进入学习 |
| 验收标准 | Given 学生已登录且已获得课程授权，When 打开课程列表，Then 只看到其已授权的课程 |
| 优先级 | Must |
| 负责人 | 待填 |
