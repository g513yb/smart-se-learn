# 故事卡

## 模板

| 字段 | 内容 |
|---|---|
| ID | `REQ-<模块缩写>-<三位序号>` |
| 标题 | 一句话 |
| 故事 | 作为〈角色〉，我希望〈行为〉，以便〈价值〉 |
| 来源 | `S-xxx` / `D-xxx` / `R-xxx`；Q 是问题，不是来源；推断写 `I-xxx` 并转 Q |
| 验收标准 | Given ... When ... Then ...（主流程至少一条，异常流另列） |
| 优先级 | Must / Should / Could / Won't |
| 优先级依据 | `D-xxx` / `S-xxx` / `Q-xxx` |
| 负责人 / 评审人 | 姓名 |
| 评审结果 / 评审日期 | 通过 / 退回 / 待评审；日期 |
| 确认人 / 确认日期 | 姓名；日期 |
| 状态 | 候选 / 已确认 / 开发中 / 已验收 / 已废弃 / 已拒绝 / 变更中 |
| 未决问题 | 关联的 `Q-xxx` |
| 冲突检查 | 结论、比对条目、未覆盖项；格式见 `references/conflict-check.md` |
| 依赖 | 其他需求或外部系统；无则写“无” |

## 填写规则

- 一条故事只表达一个用户价值。
- 只写“做什么”，不写“怎么做”；技术方案留给设计。
- 验收标准必须可观察；写不出 Then，说明需求未成形。
- 任何未确认的细节写入“未决问题”，不写进正文。
- 来源不能为空；找不到来源就提问，不写需求。
- “以便〈价值〉”也必须有来源；价值若是推断，写成 Q，不写进故事。
- 验收标准里的前置条件同样要可溯源；无法溯源的条件写成 Q。
- 用户用自然语言描述时，原话存入 S-xxx；故事卡引用 S-xxx，只做重述、拆分和用语归一化，不新增内容。
- 整理后与原意不一致时，以 Q 记录原话为准，并重新确认。

## 提交前字段检查

- [ ] ID、标题、故事、来源、验收标准、优先级、负责人/评审人、状态有值
- [ ] 未决问题已列 Q 编号；无则写“无”
- [ ] 依赖已列；无则写“无”
- [ ] 来源为 `S-/D-/R-`，可回溯；没有 `I` 推断进入“已确认”
- [ ] 冲突检查已记录结论、比对条目和未覆盖项
- [ ] 优先级依据、评审结果/日期、确认人/日期有值
- [ ] 验收标准至少一条主流程；异常流已列或写明待确认

## 示例（非项目需求）

| 字段 | 内容 |
|---|---|
| ID | REQ-LEARN-001 |
| 标题 | 学生查看已授权课程 |
| 故事 | 作为学生，我希望查看我已被授权的课程，以便进入学习 |
| 来源 | S-001（产品负责人原话：“学生登录后可以学习课程”） |
| 验收标准 | Given 学生已登录且已获得课程授权，When 打开课程列表，Then 只看到其已授权的课程 |
| 优先级 | Must |
| 负责人 / 评审人 | 待填 / 待填 |
| 状态 | 候选 |
| 未决问题 | Q-015 列表展示哪些字段？Q-016 是否支持筛选？ |
| 依赖 | 登录与授权（REQ-AUTH-xxx） |

注意：示例没有补“封面、简介、进度、筛选方式”，这些都在未决问题里。
