# 移交设计

需求阶段结束时使用。只检查和打包，不做设计。

## 1. 触发

- `STATUS.md` 当前阶段为“需求确认完成”；或
- 用户明确要求移交设计。

存在移交阻断项（见 2.1）时不移交；先按 `file-lifecycle.md` 和 `dialogue-log.md` 处理。

## 2. 前置检查

| 检查 | 依据 | 不通过时 |
|---|---|---|
| DoR 全部通过 | `file-lifecycle.md` 的 `backlog.md` 节 | 列出未通过项，停 |
| 模块门禁通过 | `coverage-scan.md` 的模块覆盖总览 | 列出“未问”维度，停 |
| 该模块 S/Q 关联列无“待建” | `dialogue.md` | 按 `dialogue-log.md` 回填，停 |
| NFR 都有编号 | `nfr.md` | 补编号，停 |
| 需求模型已定稿 | `models/README.md` | 列出“含待定点”的图，停 |
| 本模块无待回答/部分回答的 Q | `dialogue.md` | 先处理，停 |

每一关只认显式记录；没有记录就是未通过。

### 2.1 移交阻断项

以下任一项存在即不移交：

- 本模块 `dialogue.md` 中仍有“待回答”或“部分回答”的 Q；
- 该模块 S/Q 关联列仍为“待建”；
- 需求模型仍标“含待定点”；
- NFR 缺编号或缺该模块条目；
- DoR 或模块门禁不通过。

纯设计问题不保留在 `dialogue.md`；移入移交包第 5 项或 `design-notes.md`，并关闭原 Q。

## 3. 移交包

在对话中输出，不新建文件：

1. **需求清单**：按模块列 `REQ-xxx`，每条标 DoR 结论。
2. **NFR 清单**：`NFR-xxx`。
3. **需求模型**：`models/README.md` 中属于需求阶段的图；标“含待定点”的列出待定点。
4. **设计线索**：`design-notes.md` 的 `DSN-xxx`，明确“参考，不是已确认设计”。
5. **设计阶段问题**：已从 `dialogue.md` 移出的纯设计问题；逐条注明。
6. **设计入口**：数据、接口、界面、算法分别从哪里开始；AI 提议，人确认。

移交包只引用已有编号，不新增需求、不替人决定设计。

## 4. 接收方与边界

- 设计由独立的 `design-analysis` skill 承担；本 skill 不写架构、数据模型、接口、界面、算法。
- 若 `design-analysis` 尚未建立：输出移交包后报告并停，不自行开始设计。
- `design-notes.md` 在设计阶段由设计 skill 维护；本 skill 只读。
- 设计阶段发现新需求 → 退回本 skill，按 Q/S 处理；设计侧不直接改需求。

## 5. 确认与状态

- 移交包交人确认；AI 不自行判定移交完成。
- 人确认后，更新 `STATUS.md`：当前阶段“已移交设计”，当前模块“无”，下一步“设计”。
- 不记录确认人/日期；不写项目 D。

## 6. 禁止

- 不移交存在移交阻断项的模块；
- 不把 DSN 写成设计决定；
- 不在本 skill 里做设计；
- 不新建 handoff 文件；需要留档时由人确认后写入设计文档。
