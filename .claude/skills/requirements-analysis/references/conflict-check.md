# 冲突检查

新增需求、变更已确认需求、或把候选转为“已确认”之前，必须执行。目标是筛查，不是裁决；结论必须记录检查范围。

## 1. 提取冲突画像

从需求中提取以下字段；缺失字段写“未说明”，不要推断：

| 字段 | 内容 |
|---|---|
| 角色 | 谁 |
| 对象 | 对什么 |
| 行为 | 做什么 |
| 前置条件 | 何时、在什么条件下 |
| 结果 | 期望结果 / 验收标准 |
| 权限 / 可见范围 | 谁能看、改、删 |
| 规则 / 阈值 | 业务规则、数量、比例、时限 |
| 状态 / 生命周期 | 创建、修改、删除、保留、归档 |
| 时间 / 时效 | 实时、批量、延迟 |
| 数据 / 隐私 | 采集、保留、删除、匿名化 |
| 依赖 | 其他需求、外部系统 |
| 范围 | 是否触及愿景、非目标 |
| 术语 | 使用到的术语及定义 |

## 2. 检索候选

在以下文件中查找与画像字段重叠的条目：

- `backlog.md`：同角色、同对象、同行为、同术语
- `nfr.md`：同质量属性、同约束
- `vision.md`：目标、非目标、成功标准
- `glossary.md`：术语定义
- `context.md`：其他文件不收录的稳定业务事实

## 3. 逐项比对

| 冲突类型 | 检查问题 |
|---|---|
| 行为互斥 | 同一角色、对象、条件下，一个允许、一个禁止？ |
| 结果矛盾 | 同一触发条件下，期望结果不同？ |
| 权限矛盾 | 角色可见或可改范围重叠且结论相反？ |
| 规则 / 阈值矛盾 | 同一规则出现不同数值、比例、时限？ |
| 状态 / 生命周期矛盾 | 一个要求可变、可删，另一个要求不可变、保留？ |
| 数据 / 隐私矛盾 | 保留 vs 删除、审计 vs 匿名、采集 vs 最小化？ |
| 依赖矛盾 | A 依赖 B，另一条禁止或改变 B？ |
| 范围 / 非目标矛盾 | 触及愿景中的非目标或范围外内容？ |
| 术语矛盾 | 同一术语在不同条目中定义不同？ |
| 优先级 / 容量矛盾 | 两条 Must 无法在同一迭代完成？ |

## 4. 结论分类

- **确定冲突**：两边文字明确矛盾，可直接引用原句
- **可能冲突**：同一领域但语义不明确，需要人判断
- **无冲突**：已检查上述维度，未发现重叠或矛盾
- **无法判断**：缺术语、规则、范围或权限信息，先写 Q

“无冲突”只表示已检查的维度内未发现，不是绝对保证。

## 5. 记录格式

按结论写入对应记录：

- 确定冲突：写入 `decisions.md` 的 `D`；
- 可能冲突 / 无法判断：写入 `dialogue.md` 的 `Q`，检查结论写在 Q 的依据列；
- 无冲突：只在对话中说明，不写文件。

记录格式（写入 D 或 Q 的依据时使用）：

```
结论：确定冲突 / 可能冲突 / 无冲突 / 无法判断
检查维度：角色、对象、行为、规则、权限、范围、术语、NFR、依赖
比对条目：REQ-xxx、S-xxx、NFR-xxx
依据：引用双方原句
未覆盖：缺术语定义 / 缺非目标 / 缺权限规则
处理：D-xxx / Q-xxx
```

## 6. 处理规则

- **确定冲突**：停止，不进入 backlog 或“已确认”；进入冲突决策，列选项，由用户决定；处理顺序见 `dialogue-log.md`
- **可能冲突**：生成 Q，等确认；不得自行判定兼容
- **无法判断**：生成 Q，补齐术语、规则或范围；不得标为“无冲突”
- **无冲突**：记录检查维度
- **高风险**：权限、隐私、删除、保留期、范围或非目标 → 由人在对话中确认
- 决策后的结果记 `D`；需求文件不设状态字段，需求内容直接更新，旧值由 `D` 的影响需求列说明。

## 7. 不得做的事

- 不得只凭记忆判断
- 不得在缺术语或规则时假定兼容
- 不得替用户在冲突选项中选择
- 不得删除或改写旧需求来“消除”冲突
- 不得把“未发现”写成“没有冲突”
