# 建模指南

建模是为了回答一个具体问题，不是为了画全。每张图先写清“它回答什么问题”。

| 图 | 回答什么问题 | 何时画 |
|---|---|---|
| 用例图 | 有哪些角色、系统边界在哪 | 新模块或角色不清时 |
| 活动图 | 业务流程有哪些步骤、分支、异常 | 流程复杂或有多角色协作时 |
| 时序图 | 角色、系统、智能体之间如何交互 | 涉及外部系统、智能体调用时 |
| 状态图 | 对象有哪些状态、如何迁移 | 学习记录、诊断、画像、数字孪生等有状态演进时 |
| 领域类图 | 核心概念及关系 | 术语多、概念易混淆时；不是数据库设计 |
| 上下文图 | 系统与哪些外部系统相连 | 确定系统边界时 |

## 规则

- 一图一文件，Mermaid 源码，文件名与图题一致，放在 `docs/requirements/models/`。
- 图上不出现没有来源的字段、规则或角色；发现缺口记为 Q。
- 图与文字冲突时，以有来源的一方为准，并记录冲突。
- 不为汇报补图；汇报需要的图从已确认的模型中挑。
