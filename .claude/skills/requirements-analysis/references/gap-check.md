# 缺口检查

1c 的执行规则。缺口不是“AI 觉得还缺什么”，而是固定检查项没有明确依据。

## 1. 缺口的定义

缺口 = 一个固定检查项，在当前已知状态中没有明确、适用、已确认的答案，且它是完成当前需求或模块覆盖所必需的。

## 2. 缺口类型

| 类型 | 含义 | 例子 |
|---|---|---|
| 信息缺口 | 四问或故事卡字段没有答案 | 学生查看记录的触发场景未说明 |
| 覆盖缺口 | 27 项扫描中未覆盖、部分覆盖或无法判断 | 课程结束路径未问 |
| 依据缺口 | 需求没有 S/D/R；主动候选没有 P | “学生应能删除记录”没有来源 |
| 术语缺口 | 术语未定义或歧义 | “班级”“完成”未定义 |
| 规则缺口 | 业务规则、阈值、例外未定义 | 完成条件谁定、例外谁批 |
| 范围缺口 | 模块边界、非目标、角色范围未定义 | 某模块边界未定 |
| 一致性缺口 | 已知项之间矛盾 | 保留 3 年 vs 学生可删除 |

一致性缺口转 `conflict-check.md`；其余缺口转 Q。

## 3. 检查项

按当前单位选择：

| 当前单位 | 检查项 | 来源 |
|---|---|---|
| 一条需求描述（A 路径） | 成形四问 + 故事卡字段 | `elicitation-playbook.md`、`story-card.md` |
| 一个模块（B 路径 / 扫描） | 27 个子提问 | `coverage-scan.md` |
| 角色 / 职责 | 角色定义、目标、场景 | `01-personas.md` |
| 术语 / 规则 / 范围 | 术语表、上下文、愿景、非目标 | `glossary.md`、`context.md`、`00-vision.md` |

只检查这些固定项；清单外发现标为“清单外建议”，需用户批准。

## 4. 判断步骤

0. 用户用自然语言描述时，先在 `07-dialogue.md` 记 `S-xxx`，保存原话；后续缺口 Q 的依据引用 `S-xxx`。

对每个检查项，按固定顺序查找：

1. S 用户原话/回答（状态已记录或已确认）
2. 已确认需求（`REQ-`）
3. 稳定知识（`context.md`、`glossary.md`）
4. 已问待答 Q
5. `R-` / `NFR-` / 愿景
6. 模块 brief（`P-`）：只作提问依据，不作答案

判定：

| 已知状态 | 结论 |
|---|---|
| 有显式、适用、已确认的答案 | 无缺口 |
| 只有部分答案 | 缺口（部分覆盖）；提更窄的 Q |
| 只有待答 Q | 无新缺口；引用原 Q |
| 没有答案 | 缺口；提 Q |
| 有明确范围排除声明 | 不适用；不是缺口 |
| 缺术语、规则或范围，无法判断 | 缺口；提定义或范围 Q |

规则：

- 必须有显式引用；没有引用就是缺口。
- 引用必须同主体、同范围、同属性；不确定时写“部分覆盖”或“无法判断”。
- 不适用必须有明确排除声明；AI 自己判断不算。
- `P` 不作答案；`P` 只能帮助提问。
- `S` 是来源，`Q` 是问题；Q 的回答另记 `S-xxx`。故事卡来源只写 `S-/D-/R-`。
- 已被待答 Q 覆盖的，不重复提问；引用原 Q。
- 设计细节不是需求缺口；进 `DSN-`。

## 5. Q 模板

```
Q-xxx 【检查项】<具体开放问题>
依据：检查项「...」+ 已知状态：<无 / 只有 S-xxx 或 Q-xxx 部分覆盖 / 缺术语...>；如有 P 观察，追加 P-xxx
确认人：
关联需求：待建
```

## 6. 停止条件

- 所有检查项都已分类
- 没有写出需求或故事卡
- 没有替用户回答
- 范围缺口未解决时，停止其他功能检查

## 7. 示例（通用示例，非本项目）

A 路径：用户说“学生应能查看课程进度。”

0. 先记 `S-001` 原话；缺口 Q 的依据引用 `S-001`。
- 角色：还有谁？→ Q
- 触发：什么场景？→ Q
- 异常：失败、越权时？→ Q
- 完成：看到什么算查看成功？→ Q
- 故事卡字段：价值、来源、优先级、负责人等缺失 → Q 或待定
- 术语“课程进度”未定义 → Q
- 不写需求

模块路径：27 项扫描见 `coverage-scan.md`。
