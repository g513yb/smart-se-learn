# 非功能需求检查表

逐项问，不逐项填。AI 可以提出指标候选，标“AI 提议”；人确认后写入；无法确认写 Q。

## 类别与问题

| 类别 | 要问的问题 |
|---|---|
| 性能 | 哪个操作、多少数据量、什么条件下、可接受的响应时间是多少？依据是什么？ |
| 可用性 | 允许的中断时长？降级时哪些功能必须保留？ |
| 安全 | 谁能访问什么？认证、授权、审计要求从哪来？ |
| 隐私 | 采集哪些个人数据？保留多久？谁能查看？依据哪条规定？ |
| 可解释性 | 分析、推荐、预测类结论需要向谁解释到什么程度？ |
| 兼容性 | 必须支持哪些端、浏览器、设备？ |
| 可维护性 | 内容、规则、模型由谁更新？更新频率？ |
| 合规 | 是否涉及学校制度、等保、个人信息保护要求？ |

## 字段定义

- **指标**：可测量的质量目标，写成“指标名 + 数值 + 单位 + 测量口径”；无法用数值表达的，写成可验证的规则。例如 `P95 响应时间 ≤ 1s`。
- **场景与边界**：指标成立的条件，写清适用的操作/使用场景、数据规模、并发、环境、时间窗口、角色。例如 `100 门课程、并发 50 人、校内网络、工作日 8:00–18:00`。
- 测量口径放在指标里；数据量、并发、环境等放在场景与边界里。

## 规则

- 对话层按 `conversation-style.md` 说明指标依据；文件不标来源。依据可以是 `S/D`、已写入文件或人的确认。
- 指标必须写成“指标名 + 数值 + 单位 + 测量口径”，或可验证的规则。
- 场景与边界至少写清适用的维度；整行必须可验收。
- 没有依据的指标或边界：AI 可以提出候选，标“AI 提议”，人确认后写入；无法确认写 Q。
- 文件不设状态、不记录评审/确认/D。

## 写入

1. 逐项问，不逐项填。
2. NFR 与 backlog 并行；不等待 backlog 完成；写 NFR 前检查相关 backlog 故事。
3. 人确认后写入 `03-nfr.md`。
4. 变更由人确认后更新；不记状态。
