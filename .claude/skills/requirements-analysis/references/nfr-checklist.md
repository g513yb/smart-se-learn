# 非功能需求检查表

逐项问，不逐项填。没有来源或决策的指标，写成 Q，不写数字。

| 类别 | 要问的问题 |
|---|---|
| 性能 | 哪个操作、多少数据量、什么条件下、可接受的响应时间是多少？依据是什么？ |
| 可用性 | 允许的中断时长？降级时哪些功能必须保留？ |
| 安全 | 谁能访问什么？认证、授权、审计要求从哪来？ |
| 隐私 | 采集哪些个人数据？保留多久？谁能查看？依据哪条规定？ |
| 可解释性 | 诊断、推荐、画像的结论需要向谁解释到什么程度？ |
| 兼容性 | 必须支持哪些端、浏览器、设备？ |
| 可维护性 | 内容、规则、模型由谁更新？更新频率？ |
| 合规 | 是否涉及学校制度、等保、个人信息保护要求？ |

## 规则

- 每个指标必须有 `S-/D-/R-` 来源。
- 指标必须带场景和边界，例如“100 门课程、并发 50 人时 P95 ≤ 1s”，而不是“响应要快”。
- 没有依据的数字一律写成 Q，例如“Q-0xx 登录响应时间目标是多少？”

## 写入与确认

1. 逐项问，不逐项填；没有来源或边界写 Q。
2. 指标必须有场景与边界。
3. 写入 `03-nfr.md` 时状态“待确认”；另一人评审，用户确认后写确认人/日期，状态改“已确认”。
4. 安全、隐私、性能目标必须第二人评审；涉及合规或基线时两人一致。
5. 变更已确认的 NFR 走 CR；状态：待确认 / 已确认 / 已废弃。
